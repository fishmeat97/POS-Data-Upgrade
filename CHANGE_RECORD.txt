| 檔案 | 說明 |
|---|---|
| `pos_core.py` | **去除 Streamlit 的版本**。所有轉換 / 偵測 / Mapping / 報表 / 核對 / 繳交追蹤 / 匯出邏輯，可直接 `import pos_core`，也可 CLI 執行 |
| `app_streamlit.py` | **Streamlit 版本**。只含 UI，業務邏輯全部呼叫 `pos_core`（兩個檔案需放在同一資料夾） |

```bash
pip install -r requirements.txt
streamlit run app_streamlit.py                 # Streamlit 版
python pos_core.py --pos ./pos_folder_or_zip --customer Customer.xlsx --sku SKU1.xlsx SKU2.xlsx --out report.xlsx   # 無 Streamlit 版 (CLI)
python -m pytest -q                             # 測試
```

```python
# 作為函式庫使用
import pos_core as core
res = core.run_transformation_pipeline(core.collect_pos_inputs("pos.zip"), "Customer.xlsx", ["SKU.xlsx"],
        customer_mapping_sheet="Customer data", sku_mapping_sheet="SKU data",
        config=core.PipelineConfig(duplicate_policy="flag"))
res["final_report"]; res["upload_log"]; res["store_reconciliation"]
```

## 3. ⚠ 行為變更（升級時請留意）

1. **Source Count 可能變少**：所有 template 現在排除數量空白 / 無法解析的列（B5）、表頭 / 合計列（B3）。原因會寫在 `upload_log["警告"]`。
2. **數量解析較嚴格**：`700cc`、`約12`、`2026-09` 不再被當成數字（A2/C2）。若原本靠這種寬鬆解析才有資料，會出現在警告「已排除 N 筆數量空白或無法解析的列」。
3. **T14 會多出以 D 開頭的真實品名**（A1）。
4. **更多 UNMAPPED**：Rawdata Name 對應到多個 Outlet 時不再自動取第一筆（A8）。要恢復舊行為：`PipelineConfig(ambiguous_rawdata_fallback="first")`。
5. **`SKU Mapping Status` 多一個值 `INCOMPLETE`**（A9）。下游若只判斷 UNMAPPED，請一併處理。
6. **Fallback 配對時 `店家編號` 變成 Mapping 的 Outlet No**（A8）。
7. **欄位異動**（detail / audit）：移除 `RAW_CUSTOMER`、`RAW_PRODUCT_CODE`、`RAW_BARCODE`、`UNIT_PRICE`、`TOTAL_PRICE`、`SOURCE_INNER_ROW`；新增 `QTY_UNIT`、`QTY_ORIGINAL`、`UNIT_STATUS`、`QTY_FLAG`、`RSP_STATUS`、`CUSTOMER_MATCH_METHOD`、`DUPLICATE_SUBMISSION`、`SALES_ID_CHECK`、`FILE_INDEX`、`FILE_COPY_SUFFIX`。**Final Report 的 21 欄不變。**
8. **API**：`load_sku_mapping()` 回傳 3 個值（含 log）；pipeline 全部失敗不再 raise；pipeline 回傳多了 `final_report_trace`、`sku_upload_log`、`store_reconciliation`、`customer_map`、`sku_map`、`warnings`。
9. **偵測順序**：T9 先於 T3A；CSV 與 Excel 皆為 T7 → T1；T7 的 label 改為「Generic SKU / QTY」。
10. **CSV 解碼**：不再 fallback 到 latin1。
